# Development

## Make Targets

The `Makefile` is generated by [bmk](https://pypi.org/project/bmk/) (its first line reads
`# BMK MAKEFILE <version>`) and is rewritten when bmk updates it, so this file keeps no copy of the
target list. Run

```bash
make help
```

for the authoritative, current list: it reads the target comments from the Makefile itself.
`bmk --help` and `bmk <command> --help` describe the underlying commands.

The targets used day to day:

- `make dev` -- editable install with the dev extras (`uv pip install -e ".[dev]"`).
- `make test` -- the full local gate: ruff format and lint, bandit, import-linter, pip-audit,
  pyright and pytest with coverage (doctests included through `--doctest-modules`). It also
  raises dependency floors and applies ruff's formatting and fixes, so expect the working tree to
  change.
- `make testintegration` (aliases `testi`, `ti`) -- the integration tests only.
- `make bump-patch` / `bump-minor` / `bump-major` -- bump the version in `pyproject.toml`, turn
  the `[Unreleased]` section of `CHANGELOG.md` into the new version, and rewrite
  `src/sercomm_printserver/__init__conf__.py` to match.
- `make push` -- run the tests, commit and push. Give the commit message with `MSG="..."` (it
  reaches bmk as `BMK_COMMIT_MESSAGE` and survives punctuation, newlines and `$`); without one,
  bmk prompts.
- `make release` -- tag the current version and create the GitHub release.

## Test Markers

| Command                | What it runs                                                       |
|------------------------|--------------------------------------------------------------------|
| `make test`            | All tests EXCEPT those marked `integration`                        |
| `make testintegration` | ONLY tests marked `integration`                                    |
| CI                     | All tests EXCEPT those marked `local_only` (`-m "not local_only"`) |
| `pytest tests/`        | ALL tests (no marker filter)                                       |
| `-m device`            | end-to-end tests against a real print server (opt-in, see below)   |
| `-m printer`           | end-to-end print tests; also need a printer on the device          |

No test in this repository is marked `integration` or `local_only` at present; the markers stay
available for a test that needs some other external resource.

### Device End-to-End Tests

The tests against a real print server live in `tests/test_e2e_device.py` (marker `device`). They
run only on request, because they change the device:

1. Copy `test-device.example.json` to `test-device.json` (gitignored) and describe your test
   device: address, MAC, names, firmware, and free addresses the tests may borrow.
2. Run them with `SERCOMM_E2E=1`:

   ```bash
   SERCOMM_E2E=1 pytest -m device tests/test_e2e_device.py
   ```

   The ARP-trick and factory-reset tests need root and are skipped otherwise, so run the file
   with `sudo` to include them. Print tests (marker `printer`) also need `SERCOMM_E2E_PRINTER=1`.

The suite saves the device's CONFIG to `.e2e/` before it starts and checks at the end that the
device has it back. Never point it at a production device.

## Versioning & Metadata

- Single source of truth for package metadata is `pyproject.toml` (`[project]`).
- The package reads its own metadata from static constants in
  `src/sercomm_printserver/__init__conf__.py`; a version bump rewrites that file, so do not
  edit the version there by hand.
- The console script name is the static `shell_command` constant in `__init__conf__.py`
  (`sercomm-printserver`); `[project.scripts]` in `pyproject.toml` registers it together
  with `sercomm_printserver`.

## Dependency Auditing

- `make test` runs `pip-audit` against the project environment. If it reports a vulnerability,
  raise the affected floor in `pyproject.toml` (a transitive dependency goes into the dev extras
  with a comment naming the CVE).

## CI & Publishing

The GitHub Actions workflows under `.github/workflows/` are distributed from the
`default_cicd_public` template; change them there, not in this repository.

- `default_cicd_public.yml` -- lint, type-check and test on Linux and Windows for every Python
  version listed in the `pyproject.toml` classifiers and on macOS for the newest of them, verify
  the pipx and uv installs and run the notebooks.
- `default_release_public.yml` -- on a `v*` tag, builds the artifacts and publishes them to
  PyPI, with the `PYPI_API_TOKEN` secret when it is set and otherwise through a PyPI Trusted
  Publisher (OIDC).

To publish a release:

1. `make bump-patch` (or `bump-minor` / `bump-major`), then commit and push.
2. `make release` tags the current version and creates the GitHub release; the tag starts
   `default_release_public.yml`.

## Codecov

- `make test` writes `coverage.xml`. CI uploads it with `codecov/codecov-action`; `make codecov`
  uploads it from your machine only when the `codecovcli` command is on PATH, since codecov-cli is
  left out of the dev extra (see `pyproject.toml`).
- For private repos, set `CODECOV_TOKEN` (see `.env.example`) or export it in your shell.
- For public repos, a token is typically not required.
